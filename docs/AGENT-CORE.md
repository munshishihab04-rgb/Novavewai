# J1 — bounded agent-core contract

NEW standalone Nova only; no legacy integrations or credentials. This is a local backend gate, not UI/voice, production or proof of actual model reasoning.

## Vertical and API

Authenticated `POST /conversations/:id/turns` with `{baseSequence,text,taskId?}` and the existing owner-wide Idempotency-Key atomically appends user input, creates/activates an existing nonterminal canonical task, and records a queued run. An explicit task must belong to this conversation. One active run per conversation; sequence conflicts fail closed. Replays return the original run reference and never dispatch again. `GET /runs/:id` reads state; `GET /runs/:id/events?after=0&limit=20` polls real persisted, ordered events; `POST /runs/:id/cancel` with `{}` and an idempotency key cancels. Reopen through existing message/task/artifact endpoints.

Run states: queued → running → completed | waiting_user | failed | cancelled | outcome_unknown. A question pauses the task; a subsequent explicit task turn activates it. Completion completes the task. A plain final provider message completes this run but does not assert task completion. Failures leave the task available for a new explicit turn. Never retry inference automatically. Restart recovery marks pre-dispatch queued work failed and in-flight work outcome_unknown, without calling it resumed. New turns require fresh keys; durable local tool effects remain discoverable.

## Provider and tools

Pluggable chat-completions protocol adapter, HTTPS endpoint configured by the NEW project's `NOVA_AGENT_ENDPOINT`, `NOVA_AGENT_MODEL`, `NOVA_AGENT_API_KEY`; no automatic inherited credentials or fallback. Local HTTP permitted only via explicit test-only loopback adapter construction. Credentials never enter prompts, events or responses. Unsupported/refused/truncated/malformed/error responses fail closed. Bound request context, streamed response bytes, elapsed time, model calls, tool calls and per-call schema. Redirects are forbidden. Cancellation aborts network work; post-await fences remain authoritative.

Closed v1 allowlist: `list_context`, `read_artifact`, `create_artifact`, `update_artifact`, `read_file`, `ask_question`, `complete`. Context is scoped to the run's conversation/task, uploaded UTF-8 files use the authorized encrypted store, and canonical writes share the existing artifact operations, revision hashes and optimistic bases. Every tool call has a durable input hash and receipt/event in the same transaction as its local mutation. Questions/completion are explicit terminal tool semantics. No SQL, code execution, model paths, URL fetch, identity, approval, sending or purge tool. Source content is inert/untrusted; generated content is not externally verified. Prompt instructions are not the security boundary.

## Consistency and recovery

Short owner-locked transactions revalidate owner + exact initiating session with DB wall clock. No owner lock spans provider network awaits or tool file reads. Persist the dispatch checkpoint before inference; recheck run state, session, conversation sequence, task versions and canonical artifact revisions after awaits, before every local mutation and final message. External edits invalidate stale model context. Purge cascades run data; cancellation/late output cannot recreate it. Tool results and next checkpoint commit atomically. A single application runtime per database (including non-agent/file mode) is enforced by a dedicated advisory lock acquired before file initialization or destructive recovery; this local gate deliberately does not implement distributed scheduling. Process loss retains explicit ambiguous inference rather than silently replaying it.

### Review-1 lifecycle fixes

Agent transactions perform a final exact owner/session wall-clock check after canonical, receipt, event and terminal writes. This final authorization check intentionally does not compare the pre-write context or reject the run's own newly terminal state. Expiry rolls back the entire current tool transaction; prior committed tools remain durable.

`POST /sources` rejects assistant messages with `409 generated_source_not_allowed`. Only original user messages and uploaded files are user-supplied sources. No new provenance enum/migration is introduced; existing assistant messages remain visible/exportable with their role. This does not retroactively classify old sources or detect generated text manually pasted by a user.

Lease `error` or `end` permanently invalidates that application instance, aborts active jobs, and rejects all new HTTP work with 503. Healthy DB permits `outcome_unknown/runtime_interrupted` persistence by exact run ID even if a file read is still pending. Cancelled/completed runs and purged owners are not overwritten. If DB is unavailable, durable restart recovery remains the fallback; inference is never replayed. A fresh application instance is required.

Effect transactions hold a shared handover barrier and check actual dedicated lock ownership both before work and after writes. A replacement acquires the singleton and drains old transactions under the exclusive barrier before recovery. No owner/database transaction spans provider inference. Failed file/run initialization destroys the partially acquired client; engine and dedicated client listeners are removed on close/end. The database singleton is not a cross-database file-root lock, nor a distributed lease.

## Implemented wire contract and limits

- `AgentProvider.complete(messages, tools, signal)` returns only a validated assistant message; the engine revalidates even injected adapters. `ChatCompletionsProvider` accepts one chat-completions choice, `stop` or `tool_calls`, and projects only role/content/function calls. HTTP errors/timeouts produce `outcome_unknown`; explicit refusals, malformed/truncated output, policy/budget failures produce `failed`. No retry/backoff or invented assistant fallback.
- Hard ceilings (operator may lower through server construction): 8 model calls, 16 tool calls, 4 active runs globally, 1 per conversation, 64 KiB serialized messages plus tool definitions, 64 KiB provider response, 15-second default provider deadline (maximum 30 seconds), 120-second run abort. Recent history is the latest 20 messages; context inventory is at most 50 artifacts and 16 files. Oversized context fails rather than silently dropping a current fact. Each provider request sets `max_tokens:2048`, `stream:false`, `tool_choice:auto`.
- `list_context {}` gives current task metadata, its artifact revision inventory, conversation file metadata and latest sequence. `read_artifact {artifactId}` reads this task's current canonical revision. `create_artifact {title,content:{text,language}}` and `update_artifact {artifactId,baseRevision,content}` share the public artifact writer. `read_file {fileId}` only reads this conversation's ready uploaded file. `ask_question {text}` and `complete {text}` must be the sole tool call in a response. Supported languages remain `it|bn|en`; artifact text remains capped at 20,000 characters; assistant text is capped at 16 KiB UTF-8.
- Model tool call IDs are unique per run; repeating one fails before mutation. The entire call batch is schema/allowlist/budget checked before its first mutation. Individual local tool transactions commit sequentially; an already committed tool is not rolled back if a later tool fails. Receipts preserve exactly what succeeded. Tool result data is not trusted as new instructions.
- Status projection includes `id,conversationId,taskId,status,modelCalls,toolCalls,error,createdAt,updatedAt`. Event IDs/cursors are decimal strings, ascending persisted keyset pages, max 50. Receipt detail is actual tool output, not private reasoning. Export includes safe run/event/receipt fields and message roles, never session hash or provider prompt checkpoints.
- Production CLI reads only the three `NOVA_AGENT_*` variables, all-or-none; rejects HTTP, credential-bearing URLs, queries, fragments and redirects. No production env switch enables loopback HTTP. The controlled-provider child under `tests/` explicitly permits loopback. Unconfigured agent turns return `503 agent_unavailable`; ordinary foundation routes remain usable.
