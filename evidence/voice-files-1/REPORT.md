# Voice/files vertical — bounded delivery, not deployment approval

## Outcome

Implemented native voice input → the existing authenticated conversation/turn/run/tool writer, revision-bound generated file downloads, and flexible inert uploads. No production restart, deploy, commit, trial database access, old-product changes, jobs implementation edits, or arbitrary execution capability.

**Deployment state:** live public assets deliberately unchanged because the trial reads them dynamically. `staging/voice-files/public/native.js` is the candidate integration. On a coordinated future trial restart, `scripts/trial.ts` now constructs `AzureSpeechProvider` and `buildWeb(...,{nativeVoice:true})`; the latter injects/serves the staged asset. `scripts/server.ts` supports explicit `NOVA_VOICE_MANAGED=1` with an already configured native agent. `/voice/connect` returns 410 after restart, rather than running a competing autonomous agent. Parent must approve/review deployment; nothing here claims Ricky's current UI is fixed live.

## Architecture inspected and changed

- Inspected app/runtime/migrations, native provider/tool loop, transactional artifact writer, authenticated owner/idempotency, context/provenance/privacy, encrypted file lifecycle/store, web cookie proxy, actual trial/server entrypoints, current voice UI and provider setup.
- New `voice_sessions` / `voice_inputs`, message channel/provenance and run binding (014). User audio commits observed on authenticated Azure sideband bind provider item IDs to transcripts. Browser transcript POSTs do not exist. Assistant output transcripts are never admitted as user input. Unique provider item ID plus the canonical mutation idempotency receipt and run binding prevent redispatch on duplicate events.
- Same `turn()` and `execute()` used by voice/text. Existing runtime lease checks, owner locks, exact initiating session, task/sequence/context hashes, prevalidated tool batches, final authorization checks and transactional receipts remain. Stop/barge-in cancels DB run state and aborts pending provider request; completed saved artifacts survive.
- Realtime is speech I/O only; automatic response generation disabled, no realtime tools. It receives only saved canonical assistant response for out-of-band audio. Captions display canonical messages, not untrusted browser/provider assistant transcript as user-supplied evidence.
- `create_file` uses canonical artifact/revision writer in the same transaction as receipt/checkpoint. Flat ZIP generation is in memory, source-only, no execution. Text/PDF revisions retain immutable file metadata. ZIP corrections require creating a new archive, not partial editing.
- `/files/upload` reuses existing durable reservation + encrypted blob write + authorization recheck + ready receipt writer. Original `/files` strict TXT contract retained. Owner downloads are attachment/octet-stream/nosniff/no-store. Generated downloads additionally set CSP sandbox. Sources/read_file respect extraction status and do not decode unsupported binary as understanding.

## Limits / unresolved release gates

1. **Not deployed.** Parent review and coordinated migration/restart required. Current live legacy UI is unchanged. Do not claim user acceptance on the active trial.
2. Source generation/download is supported; **terminal, code execution, preview/build and arbitrary host shell are NOT supported**. No terminal was added because no credential-free/network-free/host-isolated execution environment with quotas was established.
3. Upload transport ≤4 MiB/file, ≤16 files and ≤16 MiB/owner on flexible endpoint; old TXT endpoint retains tighter original quota. UTF-8 allowlisted code/text extraction ≤16 KiB; PDF text layer ≤30 pages and 15.5 KB extracted text. No OCR, office understanding, image/audio/video analysis, arbitrary binary understanding. ZIP uploads are inert stored bytes and explicitly unsupported extraction; no member inspection, recursive decompression or archive execution. Thus ZIP bombs/traversal are not expanded at all. Generated ZIPs ≤20 flat source entries /20,000 total UTF-8 bytes.
4. Generated text/PDF input ≤20,000 UTF-8 bytes; native context/model/tool budgets remain. Unknown filename extensions are uploadable but not necessarily readable. Generated source extension allowlist explicit in generated-files.ts. Not every allowed language is separately semantically validated or executed.
5. Voice sessions expire at three minutes; same owner has one active session; max four admitted sessions. Current global voice-capacity count is not globally serialized across different owners (release review needed for strict global quota race). Open handshake is not idempotent; response-loss recovery can leave an active server session until timeout. UI does not yet recover that lost session ID automatically. A reload cannot close an unknown ID immediately; expiry is the fallback.
6. Native voice exactly-once means same provider audio item identity, not identical text spoken as separate legitimate turns. Adversarial provider event reordering beyond the tested committed-before-completed order is not fully covered. Barge-in/stop deterministic provider tests pass; real human accent/noise/mobile microphone, multilingual native parity and real audio interruption/correction still pending.
7. Realtime read-aloud can paraphrase/add introductory speech (observed). No claim of exact speech fidelity. Browser WebRTC data channel can send provider control events; server never trusts browser assistant transcripts for persistence, but malicious client-driven independent audio generation has not been prevented at provider control level. A fully server-owned speech transport would be needed for that stronger output-control guarantee.
8. The exact-content actual correction gate failed on a trailing newline; deterministic exact artifact bytes/zip tests pass. Model instruction reliability is not universal parity.
9. PDF parser is existing fixed resource-limited worker, not a general execution sandbox. Extracted text/metadata and generated artifact source live in PostgreSQL plaintext; original uploaded blobs encrypted locally. No claim of DB encryption or universal malware scanning.
10. Upload extraction happens before reservation under ingress authentication; final mutation revalidates exact authorization, but stale-auth/parser-resource preflight and aggregate extraction concurrency deserve additional review. Existing parser CPU/memory/output/deadline and active-worker bounds retained.
11. Native plain completed replies keep task active and can be corrected through the same task. Explicit complete tool terminal tasks remain terminal; reopening them for artifact correction is unresolved. Generated ZIP cannot be edited in place. Candidate Studio directs edits via chat.
12. Jobs unchanged and **NOT live-ready**, per separate independent review. Passing historical jobs fixtures do not override robots/policy/redirect/intent blockers. No source review activation.

## Reusable implementation lessons

- Bind voice inputs on server-observed audio item commit, not browser transcript role labels. Feed one native writer, and read only post-commit assistant text aloud.
- Sideband connection open is not readiness; Azure call attachment may omit session.created. Confirm session.updated from an explicit bounded server policy update.
- Preserve file metadata on canonical text revision and validate byte caps at every revision writer, not only create/download.
- Treat unsupported upload transport as stored-but-unread with explicit receipt; never turn arbitrary bytes into UTF-8 facts.
- Test provider tool-schema descriptions against actual model use; closed validation alone is necessary but not sufficient for successful tool selection.
