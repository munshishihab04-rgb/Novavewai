Data: 2026-09-30. Nessun deploy, restart, commit; `src/web.ts`, voce, DB utenti, credenziali e vecchi prodotti non toccati.

## Cosa fa ora Nova (quando pubblicato)

**Fase 1 — carte verificate da JSON-LD (attivo di default, nessun flag).** Dopo la ricerca web, i link «a forma di dettaglio» vengono letti solo se l'origine lo permette via robots.txt (RFC 9309, UA `NovaJobBot`, gruppo specifico altrimenti `*`, longest-match, Crawl-Delay ≥1s, cache per origine 24h; 404 = permesso; 5xx/irraggiungibile = negato; 403/CAPTCHA/login mai aggirati, riportati come `BLOCKED`). Se la pagina contiene `schema.org/JobPosting` JSON-LD (nodo singolo, array, `@graph`, `mainEntity`, `jobLocation`/`address` anche come array) la carta espone titolo, `hiringOrganization`, comune/regione, `datePosted`, `validThrough`, `employmentType`, `directApply`, `observed_at`, link originale, `verification_status:'JSONLD_VERIFIED'`. `validThrough` passato → `validity:'EXPIRED'`, `status:'EXPIRED'`, mostrato con etichetta «SCADUTO»; assente → `UNKNOWN`. Publisher `UNKNOWN` salvo `hiringOrganization` che nomina un'agenzia (→ `STAFFING_AGENCY`); mai `DIRECT_EMPLOYER`. Città richiesta vs comune osservato: `CITY` / `PROVINCE_OR_REGION` (es. Castel Maggiore con `addressRegion:'BO'`) / `MISMATCH` / `UNKNOWN`. Senza JSON-LD o senza permesso il link resta suggerimento di ricerca. Max 6 pagine per run, sequenziali con crawl-delay, HTTPS solo host pubblici, 1.5 MB, 10 s, UA `Mozilla/5.0 (compatible; NovaJobBot/0.1)`. Il testo della pagina non arriva mai al modello; solo campi strutturati sanificati (telefoni/email → `[omesso]`).

**Fase 2 — Subito on-demand con Playwright (dietro flag esplicito).** Decisione del product owner registrata verbatim: *«Subito MUST be implemented with Playwright, on-demand per user request (no daily mass collection). […] The owner has accepted the ToS/robots-comment risk»*. Il commento robots (evidence/subito-claude-1/robots.txt) recita: *«It is expressively forbidden to use search robots or other automatic methods to access Subito.it. Only if Subito.it has given such permission can be accepted.»* L'adapter `src/jobs-subito-playwright.ts` gira **solo** con `NOVA_JOBS_SUBITO_AUTOMATED_ACCESS=owner-accepted` impostato server-side; assente/diverso → link di ricerca nazionale come oggi. Percorso provato di subito-claude-1: Chromium headless, JS abilitato, UA ordinario, nessun stealth/proxy/login/accettazione cookie; 1 sola pagina lista (`annunci-<regione>/vendita/offerte-lavoro/<provincia>/?q=<ruolo>`, altrimenti nazionale `?q=ruolo città`), 0 pagine dettaglio; card `article` → `h3`, `a[href$=".htm"]` con pattern `/offerte-lavoro/<slug>-<id>.htm`, `Comune (XX)`, badge. Mai paginazione `?o=`, mai `/utente/`, mai contatti/descrizione/foto/telefono; immagini/font/media bloccati; navigazioni documento oltre la prima abortite; pausa 1.5–3 s; timeout totale 25 s; cache 6 h per ruolo+città; lock globale singolo. Carte: `verification_status:'LISTING_OBSERVED'`, `status:'UNKNOWN'`, `last_verified_at:null`, publisher `UNKNOWN` (anche con «Azienda verificata») o `STAFFING_AGENCY` se il testo della card nomina un'agenzia; mai `DIRECT_EMPLOYER`. 403/CAPTCHA/timeout → `sourceUnavailable.code` veritiero (`jobs_access_blocked`/`jobs_timeout`/`jobs_busy`), mai mascherato come rate-limit.

**Dispatcher** (`src/agent.ts`, ramo jobs): fence owner/sessione/cancel prima di ogni I/O pagina e prima del lancio browser (`fenceIO`); dedup per URL; retry suppression invariata; richiesta «senza agenzie» esclude tutte le letture (nessuna prova di datore diretto) e lascia `constraintStatus:'unmet'`. Il link Subito resta se l'adapter è spento o non produce carte; gli altri link non verificati restano `searchLinks` (etichettati come suggerimenti). Nuovo campo `pageReads` (esiti per URL) e `subito` (provenienza) nel receipt.

**Renderer** (`public/app.js` e `staging/jobs-generic-1/app.js`, identici, textContent, solo link https pubblici): carta JSON-LD → «Verificato da dati strutturati dell'annuncio (JobPosting)», organizzazione, publisher, fonte, «Pubblicato / Valido fino a … — SCADUTO», comune + «comune richiesto / provincia, non X / diverso da X», «Apri annuncio originale →». Carta Subito → «Annuncio osservato su Subito · disponibilità non verificata · Inserzionista sconosciuto/Agenzia». Link di sola ricerca → invariati («non è un annuncio», «Apri ricerca sulla fonte originale →»).

## Cosa resta

1. **Non pubblicato**: nessun deploy/restart; il flag Subito non è nell'env del servizio. Il parent decide pubblicazione e attivazione (procedura release nella skill).
2. Le carte JSON-LD dipendono dai link restituiti dalla ricerca web gestita: nessuna enumerazione diretta delle bacheche; se la ricerca non cita pagine dettaglio, tornano solo link.
3. Ruolo/città richiesti non sono verificati contro il titolo JSON-LD (la ricerca «ascensorista» mostra che una pagina citata può essere di altro ruolo): la carta mostra i dati dichiarati, il modello/utente confronta. Filtro ruolo sul titolo è un passo successivo.
4. Subito: nessuna pagina dettaglio aperta → nessun controllo scadenza/data inserimento; disponibilità sempre `UNKNOWN`. Città fuori `JOB_CITIES` (12) usano la ricerca nazionale `?q=ruolo città` (non filtro geografico; la classificazione comune/provincia avviene dalla card, con `PROVINCE_CODES`).
5. Adzuna API ufficiale richiede registrazione utente (non fatta). Company/Careers discovery non implementata. Nessuna verifica identità datore (per scelta: UNKNOWN esplicito).
6. `jobs-live.ts` (registro fisso + `authorizedOrigins`) resta per compatibilità; il percorso JSON-LD è quello nuovo generico.
