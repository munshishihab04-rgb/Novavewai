## What the user can do now
- Say "Voglio fare il mio CV": Nova collects facts **one question at a time** in the fixed order name → ruolo/headline → città → esperienze → istruzione → competenze → lingue, saving each step as an **immutable artifact revision** (`cv_upsert`).
- Every value carries a server-stamped verification mark (`raccolto` / `proposto` / `confermato_utente`); the model cannot set it.
- Confirm the content and choose a template; Nova renders a **real PDF** (`cv_export`) in one of 3 layouts (moderno, classico, professionale), document language it/en/bn, and stores it as an owner-bound downloadable file bound to the exact revision.
- In the conversation, the CV card shows name/headline, **N/8 sezioni compilate**, version, template, language, an **Anteprima PDF** button (live projection of the current revision) and a **Scarica PDF** link (last export receipt; flags when it belongs to an older revision).
- Dashboard "Curriculum professionale" card still seeds the CV prompt (unchanged; now backed by a real vertical rather than a generic prompt).

## Implemented (with file map)
1. **Schema** — `src/cv-schema.ts`: closed shape (`identity{full_name,headline,email,phone,city}`, `summary`, `experiences[]{role,employer,city,start YYYY-MM,end YYYY-MM|null,bullets[]}`, `education[]`, `skills[]{name,level?}`, `languages[]{name,level CEFR|madrelingua|''}`, `certifications[]`, `consent_line`, `presentation{template_id,language,section_order}`, `verification{path→mark}`). No `photo` key anywhere (rejected as `unknown_key`; worker also refuses). `validateCv()` → list of `path:reason`; `missingFields()` fixed-order next question (it + en text); `completeness()` counts 8 sections from real data (no percentage); `cvPlainText()` projection; `cvFactsSchema` (model-facing, all keys optional). Size caps: per-field lengths, array maxima (20 experiences, 8 bullets, 8 languages…), and 24 000-byte canonical total.
2. **Storage** — existing `artifacts` / `artifact_revisions` only; **no migration 018 was needed** (`artifact_kind` not added). Revision content = `{kind:'cv',schema_version:1,cv,verification,change_summary,text,language}`; `text` is a read-only plain projection so legacy readers (editor, old PDF route) still work. `src/cv-store.ts`: `upsertCv` (merge partial facts → validate → new revision via `reviseArtifact` with `baseRevision` CAS; `revision_conflict` on stale base), `loadCvRevision`, `storeCvExport` (export stored as a generated-file artifact: exact PDF bytes + sha256 + `{artifactId,revision,template,language,template_version}`; served verbatim with integrity check, never re-rendered). Guards in `src/artifacts.ts`: a structured CV revision cannot be followed by free text (`cv_structured_only`); export receipts are immutable (`cv_export_immutable`). Old artifacts unaffected (full suite green).
3. **Agent tools** — `src/agent-tools.ts`: `cv_upsert{artifactId?,baseRevision?,facts,change_summary}` (non-strict because partial by design; merged CV validated server-side) and `cv_export{artifactId,template∈3,language∈3}` (strict). `src/agent.ts` dispatcher: `cv_upsert` runs inside the fenced transaction and stamps verification from the **latest user turn** only; `cv_export` loads the current revision under the fence, renders in the sandboxed python worker outside any transaction, then stores under a fresh fence; errors (`revision_conflict`, `invalid_cv`, `not_a_cv`) are returned as tool results so the model can recover; unknown artifact → `tool_not_found` (owner isolation). OPERATING RULES gained a concise "CV FLOW" paragraph (one question at a time, never invent, recap + confirm + template choice before export, re-export after changes). `src/identity.ts` CAPABILITIES: honest lines keyed on `cv_upsert` / `cv_export` (disappear when the tools are not offered — tested).
   - **Verification stamping rule** (`src/cv-store.ts`): `raccolto` if every string leaf of the value appears verbatim (case/space-insensitive) in the latest user message; `confermato_utente` if that message matches an explicit confirmation phrase (confermo / è giusto / esatto / va bene così / I confirm / that's correct / ঠিক আছে …) — applies to **every field touched by that upsert**; otherwise `proposto`. **Limits (documented in code):** lexical only; turn-level (cannot express "confermo il nome ma non la data"); cannot detect sarcasm/negation ("non confermo" still matches "confermo" → known false positive); never certifies truth.
4. **Renderer** — `scripts/document-worker.py` new mode `render-cv` → `scripts/cv_layouts.py` (reportlab, A4, DejaVu): **Modern** (#245c43 full-height sidebar with contatti/competenze/lingue/certificazioni, name + green headline, later pages main-column only), **Classic** (DejaVuSerif if present else Sans, centered header, thin rules), **Professional** (two-column header, grey rules under section titles). All: right-aligned dates, bullets, `KeepTogether` blocks, footer "CV generato con Nova · dati forniti dall'utente · Pagina N", labels in it/en/bn (bn labels bilingual). HTML-escaped everywhere. `src/cv-render.ts` validates template/language/CV before spawning the worker. Preview route `GET /artifacts/:id/revisions/:rev/pdf?template=&language=` (`src/capabilities.ts`) now renders CV revisions with the CV renderer and falls back to the legacy text renderer for plain artifacts.
5. **UI** — `public/app.js` `renderCards()` (textContent only, no innerHTML): `.resultcard.cv-card` with kicker, name, headline, "N/8 sezioni compilate · Versione v · Modello · Lingua", progress bar, **Anteprima PDF** (`window.open` of the API preview URL for current revision/template/language) and **Scarica PDF** (`/api/artifacts/<file>/revisions/1/download` of the latest export receipt, folded into the card instead of a separate artifact card). `public/dark.css` additions. `/workspace` (`src/web.ts`) exposes a compact `cv` card projection (never the full content) for CV artifacts.

## Not implemented (explicit)
- **Photo**: by design never accepted (schema + worker reject).
- **DOCX export**: no. PDF only.
- **Import from an existing PDF CV**: no (the generic `read_file` PDF extraction exists, but there is no CV parser/mapper to the structured schema).
- **Matching CV ↔ jobs**: no.
- **Studio editing view for the CV**: no. The editor still shows the plain-text projection read-only; a structured section editor is not built. Corrections happen in chat via `cv_upsert`.
- **Activity table / workflow state machine (mappa §A/§C)**: not added; the vertical reuses tasks + artifact revisions. Workflow states (RACCOLTA…ESPORTATO) are derivable but not persisted as a column.
- **Operation receipts / outbox / SSE events contract (mappa §D)**: not added beyond existing `agent_tool_receipts` and `outbox` events (`artifact.created/revised`).
- **Translation variants with provenance (mappa §G)**: the document language only switches labels and "oggi/present"; content is not translated.
- **Explicit "sezione vuota" marker**: a section the user declares empty stays "missing" in `missingFields` (the prompt tells the agent not to insist); no persisted `declared_empty` flag.
- **Confirmation granularity**: turn-level lexical check (see limits above); no per-field confirmation UI.
- **Live provider run**: the scenario uses a controlled provider; no real-model (Foundry) run of the CV flow was executed in this task.
- **Trial deployment**: nothing published; `public/app.js` edited in the working tree only (release procedure in the skill not run).
